# Frenet 優先的候選驗證與效能改造方案

日期：2026-10-21。狀態：已確認設計方向，尚未實作；現行 V5.2 仍使用原圖精確查詢與反向投影驗證。本文件補充既有整合計畫，不將提案描述為已完成能力。

## 目標與決策

候選生成、道路範圍與平滑度判斷統一以 Frenet 為主。以 boundaries.csv 與同版本中線資料建立可查詢道路資料；在已驗證範圍內直接比較 s/d，只有資料不確定或需額外幾何確認時才回查原圖／XY。繪圖和模擬所需 XY 仍批次產生，不為每個輸出點強制做完整反向投影。

保留五個候選 ID、每 0.1 秒控制步更新、實際 pose/yaw 起點及失敗原因。40 m 保留為現有比較基準；2026-10-22 使用者新增前視／邊界比例模式需求（例如 L/20），須另列配置並重新比較，不能將縮短前視的耗時差異全部歸功於查詢加速。

2026-10-22 補充：以 CSV／Frenet 為主要道路判斷，疑慮才回查 XY；正確及錯誤的幾何結果以帶版本 key 的 hash table 跨步／跨圈重用；整組五候選必須於控制步內回傳，未完成者逾時拒絕。快取依賴、deadline 語意與比例公式見[算法分析第四節](reports/2026-10-22_路線生成方案與模擬器驗證.md#4-後續算法改進確認需求與待定參數)。本文件以下階段順序需服從該更新需求；尚未實作。

## 已確認的瓶頸

V5.2 本來就求解 d(s)，不是需要重新改寫成 Frenet。現行 `_validate` 逐點查邊界、呼叫 `to_cartesian`；後者又呼叫 `to_frenet`，反向投影內再次查邊界，產生重複射線搜尋、弧長反解及數值積分。

[單點 profile](reports/40m_generation_profile_20261021.json)為 40 m、每條 1,601 點：總計 33.5766 秒，密集驗證累積 30.7488 秒（約 91.6%），21 次 SLSQP 合計 0.8525 秒。這是含 profiler 開銷的單一來源車況，不能代表整圈最慢時間；巢狀 cumulative 時間不可相加。一般單組約 22～25 秒，尚未達到 100 ms 預算。

## 資料與查詢設計

### 離線道路資料

- 以同一 geometry_id、map frame、s 原點與正向載入 centerline.csv、boundaries.csv 及 reference_curve.json，核對來源雜湊；不新增另一套未對齊中線。
- 道路表至少提供 s、d_right、d_left、有效狀態、區間端點、接縫政策、查詢方式與誤差／保守界的依據。
- 核對相鄰樣本之間的縮窄、射線命中切換與閉合接縫；必要時加密。不將兩端取最小／最大或有限中點測試宣稱為整段保守界證明。
- 區分道路寬度與 Frenet 可接受域：J=1−κd 門檻、投影歧義及來源一致性可能使道路內部仍不可用。尚未建立有效域依據的區間須回退或拒絕。
- 現有 ESP 歷史診斷仍有 123 個插值區間未達 0.025 m 門檻；不能因已有 CSV 而宣稱全圖可直接插值。新表須保存自己的建置方法、版本與核對報告。

### 執行期快速流程

1. 每筆來源車況定位一次，取得實際 s/d/航向誤差，保留起點誤差閘門。
2. 對五條候選共用的 s 位置批次取得參考線、法向量、κ、κ′ 與道路範圍；相同查詢共用或快取結果。
3. 在可使用快速流程的區域，批次檢查 d_right+margin ≤ d ≤ d_left−margin、斜率、曲率及 J；明確超出道路的候選直接拒絕。
4. 必要時批次使用 p(s,d)=r(s)+d·n(s) 產生 XY；單純座標轉換與完整反向核驗分成不同介面。
5. 完整精確流程保留為區域回退與離線對照，記錄回退原因、次數、耗時與最終結果。

### 回退條件與結果語意

| 情況 | 行為 |
|---|---|
| 來源版本不符或資料損壞 | 拒絕載入，不靠回退掩蓋來源不一致 |
| 無有效區間、誤差界未知、落在不確定邊界帶 | 精確查詢；失敗則明確拒絕 |
| 可能投影歧義、接縫尚未核對、低 J | 完整確認或拒絕，不直接快速接受 |
| 明確違反已確認的道路／曲率限制 | 直接拒絕並保存原因 |
| 地圖改版或新增動態障礙物 | 靜態表不能替代更新後障礙檢查；另接相應介面 |

「有問題才回查」包含可能漏判的區域，不能只對已被快速檢查判定失敗的點回查。需區分道路取樣通過、Frenet 域確認、原圖精確核驗及尚未核驗，不能全部沿用同一個通過旗標。

## 實作順序與驗收

| 工作 | 修改位置／方式 | 驗收 |
|---|---|---|
| F1 相同查詢去重 | TrackData／幾何查詢包裝層，共用同組 s 的精確資料；維持原判定 | 固定來源 pose 對照原版五 ID、通過／拒絕原因、起點與數值誤差；保存耗時 |
| F2 道路表與快速驗證 | 新增具版本及區間狀態的查詢介面；V5.2 可選 exact／fast 模式，預設不在未驗收前切換 | 含窄路、急彎、接縫、歧義、無效資料；檢查快速接受是否被精確核驗拒絕，差異必須定位 |
| F3 平行與重用 | 五候選工作分配、前一步解作初值，保留來源與決定性診斷 | 比較延遲、CPU、結果差異及程序開銷；不預先承諾線性加速 |
| F4 整合驗收 | 同一 session 40 m／每步生成至少一圈，獨立重播與瀏覽器前後播放 | 持續更新並跨接縫；保存 median/P95/P99/max、回退率及逾時數 |

F1 是判定規則不變的去重；F2 若採近似查詢或改變核驗程度，須新增明確結果語意，不能宣稱與原版完全等價。抽樣對照可作回歸證據，不等於全道路連續域證明。

即時目標仍為每 0.1 秒交付一組來源正確的候選；需要留下其他工作預算並定義逾時行為。非同步不得把舊來源結果標成當下結果，也不得讓未來資料進入回放游標。離線每步都有候選不等於牆鐘 10 Hz。

## 完成界線

此方案改善幾何路徑生成與道路查詢，不新增 MPC、候選接管、對手預測或車輛動態約束。道路內的中心點不代表完整車身可通過；footprint_verified、dynamics_verified 與連續域旗標仍須依實際驗證分別記錄，不因採 Frenet 或新增快取而提升。
