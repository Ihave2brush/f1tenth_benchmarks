# QP 加速與結果一致性驗證

日期：2026-10-14。依使用者要求處理跨終點 QP 耗時；只修改 QP 的等價數值實作，不更動局部模型、P/Q/h、Safe Set、input-rate 權重、狀態／輸入限制或原殘差 gate。

## 問題與處理

profiling 顯示四窗口的 finish solver 共約1.36s，其中 OSQP solve 約1.17s。跨線的多個分支反覆建立同一個模型／目標，只更改各stage的 before/after bound。

本次在 `controller.py` 完成：

1. 分支共用 hard-equality 的 reference／null-space basis、同一 OSQP workspace，更新 l/u，使用前一解 warm start。每次控制時刻建立新的 workspace，不把不同模型或初始量測的矩陣偷偷沿用；重用前核對等式、矩陣與objective。
2. 速度多邊形採 constraint generation：先求解較小問題，若解違反任何原始速度facet就加入該facet重解。每次仍檢查全部原始限制；不是移除速度cap。這四個窗口的最優解不需要任何速度facet啟動，因此減少了大量非活動行。另有速度cap確實啟動的測試。
3. 用完整仿射動態對 bounded control 的進度範圍，與原保守interval取交集，排除已可證明不可能跨線的分支。篩選包含浮點padding。四窗口分支數由13/11/7/1降為5/9/3/1，不改h的定義。
4. 因求解容差而僅略超過物理command上限的輸出，投影回精確上限，再以修改後輸入核對全部原動態／限制與既有gate。若投影破壞模型等式就拒絕，不只检查輸入差值。這修正了約1e-10的指令roundoff被後續strict validator拒絕的問題。
