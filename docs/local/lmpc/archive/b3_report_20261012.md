# B3：ESP Local LMPC 接線與試跑紀錄

日期：2026-10-12（Asia/Taipei）。狀態：控制器已實作並試跑；**B3 單圈尚未通過，B4 未開始。** 使用者後續新增 [B2.5 底層控制與預測模型接軌](b2_5_control_model_plan.md)：先完成 B2.5 驗收，再恢復 B3 整圈。以下保留原試跑與當時修正決策。

## 方法與新增內容

以 `b2_esp_periodic_20261008_002` 的兩個歷史來源及獨立週期模板為終端資料，重新在 core 的 ESP 起點靜止初始化。cycle=0，一次 reset；不讀舊 `resume_snapshot.json`，不把 reset 狀態接入歷史週期接縫。初始終端候選仍為最新歷史圈的 x12；候選選窗口，QP 終端不是固定等於此候選。

- [辨識／預測模型](../../../../f1tenth_benchmarks/research/lmpc/local_model.py)：只用原始實測 transition，去除兩圈共有及實測延伸的重複 source ID；禁止近似接縫和週期模板參與辨識。P=80、Q=diag(.1,1,1,0,0,0)、h=10、Epanechnikov 依論文。
- [OSQP 控制器](../../../../f1tenth_benchmarks/research/lmpc/controller.py)：N=12、dt=.1；兩圈各 K=20，硬性六維終端凸組合、單一 lambda 同時決定終端狀態與 T-t 成本；由相同權重的後繼推進下一終端候選。
- [局部實驗規劃入口](../../../../f1tenth_benchmarks/research/lmpc/planning_scope.py)：每次精確確認候選 Frenet 轉換和 Cartesian 車身；再以原物理模型／原 PID／原延遲預演 12 步，檢查 .01 s 車身端點及 .1 s Frenet 狀態。只授予這次第一命令的 ESP 模擬使用，不改 geometry 全域驗收旗標。有限採樣不認證未採樣區間。
- [控制與紀錄入口](../../../../f1tenth_benchmarks/research/lmpc/run_lmpc.py)：每步立即寫真實 transition，並保存模型、終端來源、權重、QP 殘差、預演、一步預測誤差與耗時。失敗即停止，沒有 PP 備援。只在完整成功且 T 已知後另存成功圈 NPZ。
- [獨立檢查](../../../../f1tenth_benchmarks/research/lmpc/verify_lmpc.py)：原模型重播、QP 模型等式、硬性終端等式、lambda／後繼、80 點實測來源、程式／設定／NPZ hashes。

## 明列工程調整

本次可執行版本是 **hybrid Local LMPC pilot**，尚非論文純資料回歸模型的完整重現。

原車模的轉向 PID 用固定角速度切換，對微小命令差分的敏感度幾乎為零；直接線性化造成靜止起跑 QP 不可行。因此預測端採用物理先驗加局部加權仿射殘差，並加入實際轉向角及兩個 delay buffer 內容（9 維預測／6 維終端）。預測轉向率是 gain=1/physics_dt 的比例追蹤並 clip 至原速率限制，低速 beta 反解分母下限 .1 m/s。**實際模擬及預演仍使用原 bang-bang PID。**

原論文每個速度的五係數回歸仍保存作診斷；初次起跑的側向回歸曾出現數百／數千倍係數，完整數值秩不代表條件良好或充分激勵。殘差 ridge=.1 是工程先驗強度，不能宣稱兩圈已完整學得速度動態。歷史 PP 的加速度平均也不是精確的區間常值命令。

設定見 [lmpc_b3.yaml](../../../../params/research/lmpc_b3.yaml)。3.0 m/s 試跑曾在求解或預演側向門檻失敗；pilot 明列改為速度範數上限 1.5 m/s，不放寬 .25 m 側向、.5 rad 航向、.05 m 車身餘裕及 1e-5 等式门檻。QP 用保守 vx/ vy box 內接速度範數限制，所以直線可達 vx 約 1.4142 m/s；不能把它稱為實際固定 1.5 m/s。加速度上限3 m/s²、輸入變化權重 [.5,.01]、兩次 SQP、trust box 和求解器設定皆為工程值。

終端六維約束未加鬆弛。接近終點的 stage-cost 指標在名義預測上固定為 QP 常數，並非混合整數精確起終線最佳化。核心 `planning_allowed/domain_verified/continuous_verified` 保持 false；單圈完成也不證明非線性遞迴可行或全域安全。

## 單圈結果與目前阻礙

`b3_esp_pilot_20261012_002` 是目前最長的完整圈嘗試：171 個真實控制步，elapsed=17.1 s，s=23.886746855 m（全圈約10.08%），尚未抵達終點。一次 reset；已執行資料無碰撞或 Frenet 拒絕。最後 x 中 e_y=-.20929 m、e_psi=-.08359 rad，仍在門檻內；下一控制步第二次 SQP 回報 primal infeasible，該命令未施加。

目前直接確認的是**重新線性化後的 QP 不可行**；預測模型、硬終端可達性與各組限制的貢獻仍待 B2.5 分離診斷。不是缺少 Safe Set 的20點或其後繼：當時候選 s=25.7062 m，兩圈各20點都有來源／後繼。第一輪QP有解；重新線性化後不可行。Frenet診斷與歷史來源完整性通過，不能推論模型已足以在原致動器上達成終端狀態。

獨立 `independent_audit.json` 在当次版本下通過：1720 physics ticks 以原模型重播、tolerance=1e-12；171步最大終端殘差6.961e-7、最大模型等式殘差8.829e-7；沒有週期模板混入辨識，歷史NPZ不變。這是已執行片段的資料／QP驗證，並非B3成功。

`b3_esp_pilot_20261012_003` 另測 original_pid 名義值＋surrogate敏感度，在第1步之後就 primal infeasible inaccurate；只施加1步，獨立20 ticks重播通過。這次變體未能靠替換名義值取得持續可行的 QP；不能據此推論所有原 PID 接軌方法都不可行。此變體保留為明確的診斷選項，預設回到較長試跑的 smoothed_servo 版本；最新程式／設定另以 `b3_final_probe_20261012_001` 短程複核，不假裝舊session使用了新版hashes。

至此**沒有新成功圈 NPZ**，只有真實 raw stored data 與控制／失敗診斷。沒有增加初始化PP圈、放寬終端凸包、混入未來資料或改車模來掩蓋失敗。尚無逐圈學習、圈時改善或接近生成賽車線的證據。

原試跑時的下一步是繼續B3；目前執行順序改為先B2.5：量化原PID離散轉向相位／終端內部致動器相容性及局部預測偏差，先讓第一段彎道閉迴路通過。若需要新的激勵資料或改動初始化／原車模，須另列實驗方法偏離；不能直接把變更後的結果視為本方案通過。單圈完成、控制耗時100ms、學習改善是三種不同结論。B4 的成功圈自動匯入、連續下一圈與對照組尚未實作；B3 首圈資料固定，不使用本圈未知T的過渡資料作終端成本。若單圈失敗，保留新 raw stored data，但不建立已成功資格的 NPZ。


## 最終程式複核與耗時

最終 `smoothed_servo` 設定的 `b3_final_probe_20261012_002`：20步／一次reset，沒有失敗；獨立210 physics ticks重播通過、程式／設定／歷史NPZ hashes吻合，最大終端殘差1.004e-7、模型等式殘差5.930e-7。此20步probe不冒充整圈完成。`prediction_value_mode`將 smoothed_servo 與原PID名義值變體明確分開，沒有自動切換或失敗備援。

最長171步session的整個控制步（辨識＋QP＋候選／原模型預演＋實際模擬／觀測／raw紀錄，控制diagnostic寫入另計）平均0.25066 s，P95=0.28018 s，最大0.44511 s。因此10Hz的100ms預算不通過。一步預測RMSE按[vx,vy,r,e_psi,s,e_y]為[.000108,.00698,.08012,.01073,.00220,.000915]；這些是已執行片段的一步誤差，不能代表12步自由預測準確度；累積偏差及終端可達性是否導致本次 QP 失敗，留待 B2.5 診斷，尚未建立唯一因果結論。
