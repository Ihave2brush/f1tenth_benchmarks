# B2.5：底層控制與 LMPC 預測模型接軌計畫

建立：2026-10-12（Asia/Taipei）。狀態：規劃已插入，執行與驗收待完成。主計畫見 [lmpc_plan.md](lmpc_plan.md)，既有問題與歷史證據見 [B3 試跑報告](b3_report_20261012.md)。本文件保存在本機 LMPC 文件目錄，不納入 Git 核心。

## 1. 目的與交接

本階段回答：**在既有模擬器的底層控制下，LMPC 能否用一致的輸入與狀態，預測車輛反應並求出可執行的彎道控制？**

目前順序是 **B2 → B2.5 → B3 → B4 → B5**。B2.5 通過後才恢復 B3 整圈驗收；既有 B3 程式與試跑保留，不能將片段重播通過或 50 項歷史測試轉標為 B2.5 完成。

論文第 II 節定義轉向／加速度命令，第 IV-B 節直接辨識命令與下一步速度的關係，第 V 節也有 Arduino／servo 底層控制。差異不在於只有本模擬器有 control，而在於目前實作使用的 hybrid 模型尚未充分描述本模擬器的反應。原 PID 是已知因素，是否是不可行的主因或唯一原因仍需實驗定位。

交接成果是固定的模型／輸入契約、驗證門檻、失敗原因與短程閉迴路證據；B3 接手完整一圈，B4 接手成功圈更新與學習比較。

## 2. 目前問題、修正理由與預定做法

### 已確認的失敗與證據範圍

最長 B3 試跑只完成171個控制步、約17.1 s，停在第一彎附近 s=23.886746855 m。當時 e_y=-0.20929 m、e_psi=-0.08359 rad，已執行片段沒有碰撞或 Frenet 拒絕；**停止的直接原因是下一控制步的第二輪 SQP／QP 回報 primal infeasible，該步命令沒有施加。** 第一輪 QP 有解，兩個歷史來源各20點及其後繼也都有資料。因此目前不能將失敗解釋為沒有歷史點，或車輛已經撞出賽道。

同一原 PID 與車模已讓 PP 以1.2 m/s目標速度完成兩圈；但這只證明那條控制序列能行駛。LMPC 要自行求出新的轉向／加速度，還必須預測它們在延遲、轉向切換及物理限制下的結果。**原紀錄精確重播通過，不代表 LMPC 的近似模型足夠準確，也不代表每次硬終端 QP 都可行。**

下面依序列出需要處理的問題。「待驗證」表示可能影響結果，尚未證明是本次不可行的原因；預定修正須經第4節的診斷／驗收後才採用。

### 修正的先後順序與程式範圍

先完成 **A 輸入對齊 → B 獨立預測驗證 → C 凍結故障診斷**，再在 **D 選定修正**。最先比較的是「致動器反應／局部模型」與「從真實狀態重推演 warm start」；終端記憶的改動必須由相容性證據支持。最後以 **E 靜止起步至首彎結束**驗證，不以直線20步或重播通過替代。

預計修正範圍是研究層的 [local_model.py](../../../../f1tenth_benchmarks/research/lmpc/local_model.py)（輸入定義、致動器反應、局部辨識與線性化）、[controller.py](../../../../f1tenth_benchmarks/research/lmpc/controller.py)（warm start、迭代與限制診斷），以及研究診斷／驗證工具。Safe Set／Q-function 介面先保留；只有終端相容性診斷要求時才另列變體。這些都是**預定工作，尚未修改或驗收**。

B2.5 的目的不是直接證明學會最佳賽車線，而是先讓 LMPC 在既有車模下可靠通過首彎。通過後 B3 驗整圈，B4 才驗成功歷史更新與學習，B5 比較圈時及生成賽車線。

## 3. 固定基準與資料資格

- 使用同一 ESP／core geometry_id、Frenet 座標、Continuous 生命周期及原物理積分。全域 planning_allowed／domain_verified／continuous_verified 旗標維持原狀。
- 使用既有 B1 的 1.2 m/s PP 兩圈及原始子步紀錄，B2 的 lap_001.npz、lap_002.npz、lap_002_periodic.npz 保持不變。原始來源 hash 驗證通過後才使用。
- N=12、dt=0.1 s、K=20／來源圈、P=80、辨識 Q、h 與核函數維持論文設定。Safe Set 與 Q-function 的基本介面保留。
- 原 PID、轉向 delay／速率限制、車輛參數先固定；模型變體、正則化與輸入適配是獨立研究設定。若需更改原車模、初始化或新增激勵資料，另建實驗與來源紀錄，不追溯改寫既有驗收。
- 近似週期接縫與週期模板只作終端歷史，禁止加入辨識或當成獨立預測驗證量測。B3 失敗片段可供診斷與預先指定的訓練／驗證使用，不能成為成功終端來源。
- 診斷重播／原模型預演不是新增成功圈；本階段不默默增加第三個 PP 初始化圈。

## 4. 工作順序

### B2.5-A：輸入語意與致動器重播

沿原始 samples 的 source ID 還原同一時刻的七維物理狀態、六維 Frenet 狀態、實際轉向角、兩個 delay buffer 內容與時鐘。

明確分開 delta_command、delayed_target、actual_steering、steering_rate，以及 PP target_speed、LMPC acceleration_command、每子步 applied_acceleration。原始 row 記錄 incoming transition，x_i 到 x_(i+1) 的輸入應取 row i+1。每個控制區間是10個 .01 s物理子步。

用原模型與原 PID target 序列重播，物理狀態／buffer 容差沿用已驗證的 1e-12；另核對加速度入口的原 PID 反解與施加限制。**PP 區間平均加速度只是一個描述值，不能當成精確的10子步常值輸入。** 若模型需要平均量，須明列近似並量化其誤差。

輸出輸入欄位契約、實際時間對齊、delay／轉向切換反應及精確重播結果。這一步不修改底層 PID。

### B2.5-B：已知成功資料的預測驗證

先驗證已有成功行駛，範圍包括靜止起步、直線、第一彎、全圈代表彎道及真實跨線。按曲率與致動器飽和／切換分類，不能只報全圈平均誤差。

比較一步預測及12步自由推演。一步檢查使用當下實測狀態；自由推演只在窗口起點使用量測，後續狀態由模型遞推。12步使用該段已記錄的輸入，是離線預測測試，不是允許線上 LMPC 讀未來命令。另報每步用實測狀態校正的結果，但不可用它代替自由推演。

辨識與驗證資料分開。若第一圈訓練、第二圈驗證，**第一圈 NPZ 的實測延伸已包含第二圈資料，必須按 raw source ID 排除這些延伸**，並去除共有邊界／transition 重複，避免資料洩漏。靜止起步只存在第一圈，另列可取得的驗證證據與限制；需要補充短程診斷時另存，模型固定後才評估。

比較論文的五係數局部加權回歸與既有 hybrid 模型。保存奇異值、條件數、有效樣本數、係數與驗證誤差；數值滿秩不代表資料有足夠激勵。正規化、正則化、致動器擴充或不同輸入定義須明列工程來源。

### B2.5-C：失敗現場與終端相容性診斷

保存 B3 最長試跑第171步的現場：s=23.886746855 m，當下完整物理狀態／buffer、終端候選、40個歷史點與後繼、lambda／成本、每次線性模型、求解設定與殘差。先重現第一輪有解、第二輪不可行的情形；允許現行程式與歷史版本有差異，但必須記錄，不能宣稱重現了沒有保存的版本。

比較上一解移位的初始預測軌跡，以及從當下真實狀態／buffer 重新推演的軌跡。量化各狀態的模型等式缺口與迭代前後可達集合變化。

分組診斷模型、硬性終端、物理上限、狀態限制與 trust box 對不可行的貢獻。若使用鬆弛變數，只能用於離線找原因，結果不施加至車輛、不納入成功資料、不當成硬終端通過。

按 source ID 取得終端歷史點的 actual_steering／buffer，檢查相同六維狀態或同一凸組合是否具有可接續的致動器狀態。六維狀態可能未完整描述帶延遲的系統；但加入三維終端約束也可能縮小可行集合，先診斷再決定。任何擴充均須說明對論文六維 Safe Set／後繼推進的改動及限制。

### B2.5-D：選定模型與修正接軌

依 A～C 的證據選擇修正，不預先認定平滑 servo、原 PID 名義值＋surrogate 敏感度，或更強正則化必然可行。模型候選須在一致的輸入層、資料切分、致動器記憶與實測限制下比較。

可先研究：命令到致動器反應的局部辨識／有限幅度取樣、物理先驗的誤差來源、每步從真實狀態重新推演，以及終端致動器相容性。若使用原 PID 取樣建立仿射近似，取樣幅度與有效範圍也須記錄，微小差分得到零敏感度不能被當成沒有控制作用。

模型／限制／誤差門檻固定後，再評估獨立驗證區間。調參資料與最終評估資料分開；不能看到失敗才放寬門檻。本階段保留原硬性終端凸組合與共享 lambda 成本；需要改動時另列方法變體與重新驗收範圍。

### B2.5-E：首彎短程閉迴路與 B3 交接

沿既有新實驗方式，在 core 起點靜止開始、cycle=0、一次reset，載入固定兩圈與週期終端歷史。驗證區間按 core 曲率事先指定為「起點至第一彎結束」，至少覆蓋23.89 m故障位置及其後完整N=12預測窗口，不能只跑前20或100個直線控制步。

保存所有 QP／lambda／模型／預演、實際狀態、轉向與加速度層、Frenet／車身檢查及耗時。每次命令仍經原模型預演；不可行、候選拒絕、失效或碰撞時停止並保留資料。通過短程不等於已完成成功圈，也不生成可更新終端成本的新成功圈 NPZ。

## 5. 驗收門檻與進度

| 項目 | 門檻／證據 | 狀態 |
|---|---|---|
| 語意與精確重播 | 同一 raw transition、dt=.1、10個子步、frame／geometry／buffer對齊；原模型物理重播1e-12 | 待B2.5執行 |
| 模型資料資格 | 實測、source ID去重；週期模板排除；訓練／驗證無交叉洩漏 | 待執行 |
| 預測誤差 | 六維及實際致動器的一步／12步誤差、系統偏差、RMSE／P95／最大值；按場景分類 | 待門檻登記與驗證 |
| 失敗原因 | 凍結現場與每輪模型／限制差異、可達性、終端memory相容性診斷可重現 | 待執行 |

| 整圈與即時性 | B3另驗整圈；辨識／求解／檢查／端到端耗時分開，100ms另判定 | 留B3驗收 |

學習預測模型的誤差門檻**尚未固定**，不能拿1e-12物理重播或1e-5 QP等式門檻當作其準確度要求。執行時先保存模型驗證設定：各通道容差、12步累積偏差預算、取樣區間與選定理由，依車身／道路餘裕、觀測精度及終端可達性分配，再評估未參與調整的資料。門檻未登記或任一必要項目未通過，B2.5維持未完成。

最終選定的模型須同時有獨立預測驗證與短程閉迴路證據；成功紀錄重播只是檔案與原模型一致性，不保證近似模型能用硬終端QP到達同一狀態，也不證明非線性遞迴可行。
