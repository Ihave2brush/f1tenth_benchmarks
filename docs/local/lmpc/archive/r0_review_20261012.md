## 2. 可確認的共同基礎

### 狀態與物理車輛

論文及研究主線固定狀態順序：

\[
x=[v_x,v_y,r,e_\psi,s,e_y]^\top.
\]

實際 plant 是七維 `[X,Y,steering,v,yaw,r,beta]` 加轉向 buffer。六維觀測為 `vx=v*cos(beta)`、`vy=v*sin(beta)`、`r=physical[5]`，以及同一 core tracker 的 `e_psi/s_unwrapped/d`。車身參考點採 sim_cog，map frame、geometry_id、timestamp 必須一致。

core 已提供幾何與實際位姿追蹤；六維組合在 `lmpc/state.py`。Euler、回歸、ATV 是預測層，不能與實際 Frenet 投影合併為同一操作。

實際 plant 保留原 F1TENTH single-track 模型；低速 `abs(v)<0.5` 採 kinematic 分支，高速採動態分支。轉向命令以兩筆物理子步 buffer 延遲，經 PID 產生轉向角速度；Euler 物理積分步長是 0.01 s。LMPC runner 將每次控制的物理子步設定為 10，控制區間是 0.1 s；原 simulator YAML 預設的 n_sim_steps=4 不能誤當本次 LMPC 控制區間。

重要數值區分：原 `simulator_params.yaml` 的 plant v_max=20、s_max=0.4189、a_max=9.51；`vehicle_params.yaml` 的 controller max_speed=8、max_steer=0.4。目前研究限速8與轉向0.4來自後者，不是 plant 原始上限。原先把8泛称為模擬器上限不精確，後續文件／驗收須分列來源。

### 輸入、時間與資料

固定輸入 `[δ,a]`，δ是目標轉向角 rad，a是加速度命令 m/s²。作者 BARC 回歸程式亦用 inputFeatures=[1]辨識vx、[0]辨識vy/r，支持這個語意排列。

現有適配在每個物理子步反解原速度 PID，不移除轉向延遲與速率。requested a 與 applied a 不一定相同，因為原加速度限制仍存在。六維模型能否充分描述 actuator 記憶由 R1/R3 驗收，不在 R0 預先斷言。

儲存 row t 是實際觀測 x_t；row t+1 的 incoming command 才是這個 transition 的 u_t。模型辨識需形成真實 `(x_t,u_t,x_{t+1})`，不能拿同 row 的前一個控制指令拼接。初始 reset row 的 target_speed 初始化動作不列為 LMPC acceleration transition。

全局實際 s 使用連續 core 進度；來源圈資料平移成局部 s，保留原 sample IDs。geometry.reference 用週期幾何求κ；終端距離仍在已對齊的連續 s 上算，不能用環狀最短距離替代。

### Section III 的主體

成功完整圈才有最終 T；圈內 J_t=T-t，終點 XF={s>=L}。插值圈時與離散終點分列。每個來源各選20個不同索引的最近點，構成 D_data；各欄真實下一狀態構成 S_data。λ非負、和為1，終端狀態與成本使用同一λ。

Q-function是固定候選集合內的線性成本最小化。式 (10)初始 z取最新來源的x_N，之後 z=Sλ；施加第一個控制輸入並以實際下一觀測重解。

這些規格已清楚；驗證正確性與可行性仍分別在R2/R4進行。

## 4. 可直接定稿的模型排列與數學關係

令 P_swap=[[0,1],[1,0]]。PDF式(14)/(16)展示的控制順序是[a,δ]，若程式順序為[δ,a]，則 `B_code=B_display*P_swap`。這是排列等價，不是增加模型自由度。

位置模型使用式(12)的f_pos=[f_eψ,f_s,f_ey]。位置A為完整六維梯度；位置B=0；位置C=f_pos(xbar)−A_pos*xbar。速度A取三組Γ前三係數，速度B按上述語意排，速度C取Γ第五項。

在名義點應滿足 `A*xbar+B*ubar+C=f_model(xbar,ubar)`。這是驗收條件，不是對真實plant零誤差的要求。

對曲率κ(s)的s導數：PDF寫∇x f，所以ESP平滑曲率依原式应包含曲率變化。作者BARC程式在此处註明cur constant，depsi_s=0、ds_s=1，不能直接套到變曲率ESP。現有中央差分透過κ(s±ε)包含此變化；其誤差與κ接縫處理列R3。

## 5. 跨終點與資料ready：本次更正

使用者先前提出「新LMPC開始跑出的資料可以存入歷史」，方向正確。至少要區分三種用途：

1. 当前圈 transition已跑出：可立即保存，成為真實後繼或辨識樣本；是否納入辨識还需固定來源政策。
2. 为前一成功圈補continuation：若物理上連續，按s+L對齊，可用作已完成圈的延伸；不需要新圈的完整圈時才有這個後繼。
3. 当前圈作為新的完整成功來源与Q-function：须其成功完成，才能有最终T與完整圈成本。

reset是不同物理實驗的邊界，不能直接冒充1.2m/s前圈終點的连续後繼；但現有初始化資料的圈2／圈3本就有真實連續後繼，與新LMPC靜止reset分開，不能混淆。

現有收集方式（三圈連續PP、前兩圈為source，第三為continuation）可保留資料證據。正式持續學習必須按可用資料選窗口，必要時延後替換完整source，而非要求無限圈數。具體來源釋放策略仍須在R0討論定稿後由R5實作。

## 6. R0結案門檻與下一步

可確認的基礎：core可沿用、狀態與輸入語意、transition時序、矩陣排列、Euler位置模型、Safe Set/Q-function主體、作者WLS與真實連續延伸證據、plant与controller参数來源區分。

R0尚不能整體標記完成。以下四類尚影響核心規格：

- IV的距離/kernel解讀与公開碼差異；以哪個歷史版本支持完整復現。
- 跨線h、terminal cost offset與signed suffix的完整目標等價。
- 正式X/U與额外工程检查的邊界及索引。
- 初始化nominal與新成功來源ready規則的具體選擇（保留使用者靜止起跑偏好）。

建議下一次先討論距離與回歸的原式／作者實作差異，再討論跨線目標。作者程式可以支援解讀，但不能自動覆蓋使用者「Section III、IV完整復現」的主要求。模型失敗的實驗診斷不是R0通過條件，需在規格明确後移到R3。
