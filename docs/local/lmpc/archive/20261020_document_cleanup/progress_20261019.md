## 4. A5-NO 第二次 QP：可行性與收斂診斷

原 run 沒保存完整 P/q/A/l/u 或失敗最後 x/y，因此此次為**離線重建**，不是執行時原始矩陣快照。第一輪模型、第二輪 WLS 來源與係數、重求狀態、iterations 與 residual 均吻合保存紀錄；無法對不存在的原矩陣作 bitwise 比較。

- 原問題：142 變數、605 限制；85 條等式滿 row rank；消去後 57 變數，首次送入 OSQP 136 條限制。
- 原設定 100,000 iterations；primal=0.005107322510766316，dual=3.2537224269936574e-6。
- 初始、動態、terminal 等式殘差約 1e-15；最大原始違反為 lambda[21]=-1.1792143377770126e-4，共 23 個 lambda 低於 -1e-12。
- 原始全部 605 條限制的獨立 LP 可行點，最大違反 3.33e-16；原問題不能稱為 infeasible。
- scaling=0：3,325 iterations 成功；原限制最大違反 1.87e-14，stationarity 3.92e-14。
- 保留 scaling、僅關 adaptive rho 並用 rho=0.1：15,000 iterations 成功。獨立 SLSQP 同原問題也得到一致最適值。
- reduced Hessian rank=24/57，正曲率子空間比約 8.39e7；terminal centered matrix full rank 6。不能把零曲率直接稱為非凸或無解。
- 消去等式後近零限制列再次正規化，產生約 2.366e14 的有限 bound；這是已知數值表示問題，尚未證實單獨導致失敗。

primal residual 是外部縮放／消去後問題的數值量；不能直接當車輛誤差。原始失敗最差 lambda 違反除以 0.025 與 reduced normalizer 後，對應 solver primal 0.0051073。

證據：[QP2 診斷報告](../../../../../Data/research/lmpc/experiments/A5_NO_full_20261019_001/qp2_diagnosis_20261019_001/report.md)、同目錄 `reconstruction.json`、`feasibility.json`、`matrix_diagnostics.json`、`solver_comparison.csv` 與 NPZ。

**此報告當時提出 scaling=0 為候選；以下 S1 已限制其適用性，不再視為可全面套用的修正。保留原報告作歷史證據。**

## 5. S1：scaling=0 並未跑通

先用保存的第二次 QP 重現成功，驗證原限制後才啟動唯一一次閉迴路。重用 NO history；以已保存命令重播恢復接手狀態，沒有重新採樣。history、物理 state／buffer、首輪 12 組 ABC 與 terminal 來源均核對一致。

但第一次 QP 即達迭代上限：primal=0.0006453816912304899、dual=9.169161132970699e-5。原 NO 首輪 scaling=10 成功 7,550 次，S1 改為 0 後失敗 100,000 次。故「第二次固定 QP 成功」不能推廣成完整流程成功。

S1 最後 iterate 的原始 lambda 最小值 -1.47846396529e-5、sum=0.9999999999999953；terminal／dynamic 等式誤差約 1e-14／1e-15。沒有施加命令，所以**無新的一步 ATV 誤差或控制震盪評估資料，不是誤差為 0**。未新增該首輪的獨立可行性結論。

本次已保存真正執行時的完整失敗現場：`qp_snapshots/qp_0001/` 下的原始／solver QP、最後 x/y、原變數、設定、12 階模型、terminal states/costs 與來源；`qp_assemblies/assembly_0001/` 保存 LP 前組裝。

## 6. 作者實作對照研究

完整研究另存 [QP 與 Terminal Safe Set 原始實作對照](qp_implementation_comparison_20261019.md)，包含固定 commit、函式與行號。

已確認的主要差異：

1. 論文式 (8c) 為 hard terminal；RacingLMPC 模擬有六維 terminal slack 與 lane slack；我們保留 hard terminal 與硬狀態限制。slack 是作者公開程式的選擇，不能直接當成論文必要條件。
2. 作者完整 QP 直接送 OSQP；我們另有 terminal SVD、變數／列縮放、LP reference、null-space 消去、近零列正規化與 speed facet generation。
3. 作者未固定 OSQP 版本，wrapper 只指定 verbose=False、polish=True；不能推定當年容差／rho。
4. 作者模擬 flag 只認 solved，但公開 simulator 不檢查 flag 就取控制。BARC 公開 wrapper 甚至接受 max iterations；無法確認論文實車當時是否使用該路徑。這不證明未收斂解合法。
5. 作者沒有 lambda 二次 regularization；不要誤稱作者靠此處理收斂。
